# Kmoe Download

Kmoe Download 是一个 Chrome 扩展，用于在已适配的漫画详情页中批量选择章节，并下载 `MOBI` / `EPUB` 文件。

这个项目主要用于个人学习和浏览器扩展开发研究，不是通用下载器，也不提供任何绕过网站限制的能力。

## 功能

- 批量选择章节
- 支持 `MOBI` 和 `EPUB`
- 支持下载队列、并发控制和失败重试
- 支持 aria2 下载和直接下载模式
- 记录近期下载历史
- 历史记录支持查看、导出、导入和清空
- `koobone.com` 阅读站支持从**浏览器本地缓存**直接导出漫画（详见下文）

## 导出漫画（浏览器缓存）

在 `koobone.com` 阅读站中，页面会把已经打开过的每一卷 EPUB 缓存在浏览器本地。扩展可以在**不重新下载**的前提下，把当前系列的缓存内容整理成一个带目录结构的 ZIP 导出。**ZIP 里只有漫画源文件（原始 EPUB 字节），不再附带 manifest、封面或缺失报告。**

### 缓存实际存放在哪里

| 项 | 值 |
| --- | --- |
| 存储介质 | IndexedDB（Dexie 管理），数据库名 `KOOBONE` |
| 对象仓库 | `book_vol`，`keyPath` 为 `file_md5` |
| 漫画正文 | 字段 `file_blob`，即该卷完整的 EPUB 文件（Blob） |
| 封面 | 字段 `cover_blob`（Blob，导出已不使用） |
| 元数据 | `vol_name`、`vol_author`、`vol_series`、`vol_language`、`file_type`、`islocal` |
| 写入时机 | 阅读器打开某卷且缓存未命中时（`vol_open` → 网络下载 → `db_insert`）；命中则直接读 `file_blob` 渲染 |

> 这里说的不是 HTTP 磁盘缓存，也不是 Cache Storage，而是站点自己写入的 IndexedDB。因此扩展可以精确拿到原始 EPUB 字节，无需重新解码或重新请求网络。

### 使用方式

1. 在 `koobone.com` 打开一个系列（进入该系列的书目/卷列表）
2. 页面右侧出现 `Kmoe 导出` 浮动入口，点击 `导出漫画`
3. 面板会列出当前列表每一卷的缓存状态（`已缓存` / `缺失` / `非 EPUB`），确认后点击 `开始导出`
4. 浏览器下载一个 `<系列名>.zip`，里面只有各卷的 `.epub` 源文件

两种页面状态下的行为：

| 页面状态 | 面板行为 |
| --- | --- |
| 已进入某个系列的书目列表（站点把系列写进了搜索框） | 范围锁定为该系列，不显示选择器 |
| 站点默认的「全部卷」混合库视图 | 显示「导出系列」下拉框，默认选中**已有缓存**的那个系列，只导出所选系列 |

其它交互约定：

- `刷新缓存`：重新扫描当前页面列表并重新比对缓存。站点是无限滚动加载的，列表变长后面板**不会自动重排**（避免按钮跳动），而是把按钮改为 `刷新缓存（列表已更新）` 提醒你。
- `取消`：导出过程中可中止，中止时不会产生文件。

### 一键缓存未缓存的卷

针对「已经导入但只读过一部分」的作品，可以把没缓存的卷一次性补齐：

1. 进入该系列的书目列表（站点会把漫画名填进搜索框）
2. 如果卷很多（每页 28 卷），自己滚到底把整份列表加载出来
3. 面板里确认 `总卷数 / 已缓存 / 未缓存`，点 `一键缓存未缓存卷 (N 卷)`
4. 确认后逐卷串行缓存，进度区显示 `正在缓存 3 / 64（42%）`（百分比取自站点自己的进度条），随时可 `取消`
5. 结束后自动重新检查缓存状态，并给出「成功 N / 共 M」与失败卷原因

行为边界：

- **只处理未缓存的卷**，已缓存的直接跳过
- **完全复用站点自身的缓存流程**：扩展只是调用站点自己暴露的页面全局 `window.vol_open(url, md5)`（与用户点卷封面同一个入口），下载与写 IndexedDB 都由站点完成；扩展不碰缓存结构
- **串行 + 限速**：默认卷间隔 1.5s；单卷等待上限 10 分钟；连续失败 3 次自动停；站点报「未登録 / 頁面數據過期 / 空間不足 / 写入存儲數據失敗」这类致命提示时立即停止
- **只看已渲染的卷**：不会自动滚动、也不会替站点翻页；没滚到的卷不在一键缓存范围内（面板会提示「列表未加载完整」）
- 若站点设置里选了「緩存後打開」，缓存完会被弹出阅读器，扩展会顺手关掉它
- 需要新的**主世界桥**（见下），所以需到扩展管理页重新加载一次扩展

### 为什么需要一个主世界桥

MV3 的内容脚本 CSP（`script-src 'self'`，不允许 `unsafe-inline`）会阻止隔离世界对**带 inline 事件处理器或 `javascript:` 链接**的元素调用 `.click()`，而站点的卷封面正好两者都占（`onclick="javascript:vol_open(...)"` + `href="javascript:void(0);"`）。隔离世界也拿不到页面全局的 `vol_open`。

因此 `manifest.json` 多了一条**声明式主世界内容脚本**：

```json
{
  "matches": ["https://koobone.com/*"],
  "js": ["scripts/reader-bridge.js"],
  "world": "MAIN",
  "run_at": "document_start"
}
```

它运行在页面自己的世界里，直接调 `window.vol_open`；隔离世界通过 `window.postMessage` 下达指令。这种写法不依赖页面 CSP（浏览器直接注入），也**不需要任何新权限**（无 `scripting`、无 `downloads`）。

### 已知限制

- 缺失信息只覆盖**当前页面已加载的卷**。若目标系列还没加载完，面板会明确注明这一点；滚到底部加载完毕后再刷新即可得到完整提示。
- 导出顺序：若列表里每一卷都能识别出卷号（`卷01`、`第 7 巻`、`Vol.3`…），导出会按卷号排序；否则保持页面顺序。
- 缓存中不是 EPUB 的卷（mobi / azw3 / pdf 等）会被跳过，面板里以 `非 EPUB` 标出，不做任何格式转换。
- 站点把 `file_blob` 按卷整体存储，所以导出粒度就是「卷」，不能只导出某几页。

### 导出产物结构

```text
妄想老師/
├─ 妄想老師 第01卷.epub   # 原始 EPUB 字节，未重新编码
├─ 妄想老師 第02卷.epub
└─ 妄想老師 第03卷.epub
```

除各卷 `.epub` 外不写任何其它文件：没有 `manifest.json`、没有封面、也没有缺失清单。缺失卷只在面板上提示。

ZIP 使用 STORE（不压缩）写入：EPUB 本身已是压缩包，重新压缩只会浪费时间并可能破坏体积校验；文件名以 UTF-8 记录，中文名在 Windows 资源管理器中正常显示。

### 行为边界

- **只读缓存**：只对当前列表中的 `file_md5` 逐个 `get()`，不遍历、不扫描与该系列无关的浏览器数据
  - 在「系列书目列表」下，只会读取该系列各卷的记录
  - 在混合库视图下，为判断哪些系列已有缓存，会读取当前页面上所列卷的**元数据**（不含 `file_blob` 内容）；内容只读取最终选中的那个系列
- **绝不联网**：导出路径不包含任何 `fetch` / `XMLHttpRequest`，不会触发站点下载，也不消耗站点额度（单元测试对此有静态约束）
- **字节不改写**：EPUB 以原始 Blob 直接写入 ZIP（STORE 不压缩），导出后 SHA-256 与缓存中的 `file_blob` 完全一致
- **不破坏阅读**：不调用、不覆盖站点的阅读器函数；只注入自己的浮动入口与面板，且不写入 IndexedDB（只开 `readonly` 事务）
- **缺失显式报告**：缓存里没有的卷只会在面板中列出，并说明需要先在阅读器中打开这些卷，而不会被静默补下载，也不会写入任何文件
- 单次导出上限为 ZIP32 容量（单文件 4GiB / 总计 4GiB / 65535 个条目），超出时会明确报错而不是产生损坏文件

### 相关代码

| 文件 | 职责 |
| --- | --- |
| `shared/zip.js` | 零依赖 STORE-only ZIP writer（流式 CRC32、UTF-8 文件名、ZIP32 边界校验、可中止） |
| `shared/reader-export.js` | 纯逻辑：卷列表解析、系列归类、缓存比对、EPUB 过滤与目录结构、缓存运行报告与站点提示分类 |
| `content/reader.js` | 站点内容脚本（隔离世界）：只读 IndexedDB、导出面板与进度、一键缓存调度 |
| `content/reader.css` | 面板样式 |
| `scripts/reader-bridge.js` | 主世界桥：只干两件事——回答存活探测、代调站点自己的 `window.vol_open` |

## 安装

1. 克隆仓库：

```bash
git clone https://github.com/Fyhax1ki/kmoe-download.git
```

2. 打开 Chrome，进入 `chrome://extensions/`
3. 开启右上角的“开发者模式”
4. 点击“加载已解压的扩展程序”
5. 选择本项目根目录

> 导出漫画功能需要 `https://koobone.com/*` 站点权限。若你之前已经加载过扩展，请在 `chrome://extensions/` 中点击一次“重新加载”，然后刷新阅读站页面。

## 使用方法

1. 打开已适配的漫画详情页
2. 等待页面内容加载完成
3. 点击页面右侧悬浮入口中的 `MOBI` 或 `EPUB`
4. 选择章节和下载参数
5. 点击“开始下载”
6. 通过扩展弹窗查看或管理下载历史

默认使用 aria2 下载模式。使用前需要在扩展弹窗中打开“aria2 配置”填写 JSON-RPC 信息；如遇到 aria2 环境不可用，可以切换为直接下载。

## 设置

扩展弹窗中可以调整：

- 并发下载数
- 下载间隔
- 最大重试次数
- 下载方式
- aria2 RPC 地址、Token、下载目录和连接参数

设置会自动保存，并用于后续下载任务。
